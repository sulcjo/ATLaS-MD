## Adaptive λ ladder (`--ap-ladder-adapt respace`, off by default)

- Files: `gareus/adaptive/ladder_adapt.py` (`CentreRungModel`/`fit_centre_model`, `aggregate_overlap`, `design_ladder`, `plan_ladder_change`, `load_centre_rung_samples`, `phase_dirs`, `replay` + CLI `python -m gareus.adaptive.ladder_adapt replay <adaptive_dir> --phases ...`); in `gareus/adaptive_production.py`: `_propose_ladder_respace`, `_resolve_ladder_settings`, action `respace_ladder` (`_apply_respace_ladder`, `_retire_rung_at_every_centre`), `AdaptiveDecisionPolicy.ladder_*` + `max_replicas_budget`, applied-actions ledger (`_snapshot_pre_action_registry`, `_record_applied_actions`, `_load_applied_actions`). Plan: `docs/superpowers/plans/2026-09-29-adaptive-lambda-ladder.md`. Tests: `tests/test_ladder_adapt_*.py`, fixtures `tests/ladder_adapt_fixture.py`.
- Principle: one centre, rungs differ only in boost strength — each sample's reduced energy at ANY lambda recomputed from `v_pep_kj_mol`/`v_dih_kj_mol` + frozen envelope (`pep_gamd_boost_kj`); per-centre MBAR over that centre's rungs predicts overlap O(a,b) = ∫ p_a p_b/(p_a+p_b) (0..0.5, pairwise MBAR scale) between any two lambda values. Boost NOT linear in lambda (dependent dual boost puts dihedral boost inside Total channel's square) — never interpolate energies.
- Decision: fewest rungs where every adjacent 10th-percentile-over-centres overlap >= `--ap-ladder-min-overlap` (0.25), endpoints lambda = 0 and top rung fixed, then equal-overlap spacing (lambda grid 0.005). Change of <= `--ap-ladder-max-moves` (2) interior rungs = whole design, applied atomically at epoch boundary (intermediate ladders never run, respace keeps rung count, needs no replica headroom). Replaces weak-edge `add_rung` proposer when on; numbered epochs only (never final phase). New rungs = new state ids; retired rung states stay in union MBAR.
- Settings frozen in `adaptive_production/ladder_adapt_settings.json` at first use; `--ap-ladder-adapt-override` replaces them. Report per epoch: `epoch_NNN/ladder_adapt_report.json`.
- Applied-actions ledger (all campaigns, not only ladder): after every epoch's `registry.save`, `epoch_NNN/actions_applied.json` records actions + registry digest, `epoch_NNN/state_registry_pre_actions.json` the pre-action registry. Resume finding matching ledger re-enters that epoch on pre-action registry (map, MD, diagnostics, reports describe states that ran), never proposes/applies again. Closes pre-existing hazard (kill between `registry.save` and summary write re-entered epoch with states its window map never ran). Verified end to end through real epoch loop (`tests/test_ladder_adapt_resume_e2e.py`, kill right after save + ledger). Residual: recovered epoch re-runs optional tICA refit (coverage actions not re-applied).
- States created by epoch's actions get seed: `_reassign_seeds_after_actions` re-runs `select_state_aware_seeds_for_targets` right after actions applied (bank's assignment written before them, so scheduled segment holding only new states used to get `filter_seed_bank_for_state_ids`'s `generic_fallback`, bank's first rows whatever their CVs). Scoring = CV distance only, so new rung gets its centre's seed.
- Real-data replay (read-only): chignolin_9 final phases, 59 centres — predicted median rung overlaps 0.244/0.272/0.404 vs union pairwise 0.243/0.272/0.402; design [0, 0.175, 0.47, 1] (q10 0.281/0.281/0.286, from 0.209/0.248/0.396). chignolin_7: [0, 0.18, 0.46, 1] (0.29). Both: keep 4 rungs, move interior down. No MD run with it yet.

## CVaux Stage A (`gareus/auxiliary_cv/`, spec `docs/superpowers/specs/2026-10-07-auxiliary-cv-gibbs-production-spec.md`)

- Built: frozen model `atlas-aux-cv-model-v1` (`AuxModel`: z = (offset + Σ c f)/scale, `periodic_imaging` "none", identity = content sha incl. scale/imaging, label/provenance excluded, -0.0 canonicalised; registries embed `identity_mapping()`), OpenMM-convention dihedral features (theta = OpenMM `theta` = -tica angle; `negated` feature = trig(-theta)), exact evaluator with Blondel-Karplus gradient (FD-verified), `CustomCVForce` `ATLaSAuxCVUmbrella` = select(aux_k, 0.5 aux_k (z - aux_c)^2, 0) with exact energy/force parity, state schema `atlas-fixed-state-v2` (`aux_models` registry, per-window aux_model_sha256/aux_center/aux_k, required `instance` {state_instance_id, state_role, spawn_parent_state_id (parent's state_instance_id), spawn_source_observation, matched_additional_slot_id}, role ⇔ aux_k enforced, `hamiltonian_sha256` keyed on model sha), field `aux_k` kcal/mol/z² (deviation from spec's `aux_k_kcal_mol`); k = 0 is exact-zero energy, NaN forces at degenerate torsions (as stock OpenMM), `reconstruct_bias_matrix(aux_z=)`.
- Not wired: nothing in production, exchange, storage or analysis calls it yet (Stages B/C). v1 definitions hash byte-identically (pinned test). MVP: one model; >1 refused ("Stage F").
- Stage B owns:
  - the exchange-energy/schema version `state_bias_matrix_v3_aux` (spec 5), with separate zero-feature regression tests proving v2 compatibility;
  - **runtime detection of degenerate torsion geometry before integration** (spec 3.3). The force returns NaN forces at a degenerate torsion even at k = 0, and a finite energy at k > 0 where the evaluator raises.
- Stage D owns:
  - extending `check_feature_atoms` beyond phi/psi if the recovered c10 artifact contains omega or terminal torsions;
  - cross-arm W/B slot pairing (one table checks only its own slots).
- Stage C handoff: stored theta must be bound to the model's ordered quad list (unique_torsions first-appearance order), not only its width — permuted columns are undetectable by shape.
- Topology check is single-chain-aware (same chain, consecutive residues); omega/terminal torsions unsupported (Stage D). `z_from_dihedrals` refuses theta not shaped (n_frames, n_unique); a state may not be its own spawn parent.
- Recorded deviations: `aux_k` naming; one registered model; same-table parent rule.
- Tests: `tests/test_aux_cv_*.py`, fixture `tests/aux_cv_fixture.py`.

## Torsion-PCA CV2 — `bootstrap_torsion_component` is a count, not an index

- `compute_bootstrap_torsion_pca` (`gareus/tica.py`) previously took `component` as 1-based index selecting *single* PCA eigenvector as `cv2: torsion-pca` direction. Changed: `component` now **count** — top N components (by variance, ranked 1..N) combined into one unit-norm direction via variance-weighted linear combination, `coefficient_i = sqrt(variance_i)` then renormalized. CV2 stays single scalar restraint either way; lets one restraint draw on more than PC1 alone.
- `component=1` exactly backward compatible: single positive scalar coefficient doesn't change normalized direction's identity, reduces to old "PC1 alone" bit-for-bit.
- Default changed `1` → `5` (`--bootstrap-torsion-component`, `gareus/cli.py`; same default fallback in `gareus/production.py`'s `getattr`).
- Important asymmetry: PC1 *by construction* single direction of maximum variance, combining more components can only match or **reduce** that direction's explained variance (`TICAResult.eigenvalue`/`explained_variance_ratio`) relative to PC1 alone — payoff isn't more variance, it's picking up influence from mode PC1 doesn't see (e.g. torsion loading heavily only on PC4).
- Tests: `tests/test_bootstrap_torsion_cv.py::test_bootstrap_pca_component_count_combines_top_n_variance_weighted` verifies coefficient ratio matches `sqrt(variance_i/variance_j)` exactly and combined-direction variance strictly ≤ PC1-alone variance; `test_bootstrap_pca_component_out_of_range_raises` covers bounds check. `test_bootstrap_pca_fail_closed_on_zero_component_variance` updated for new semantics (old test's X made requesting component=2 trivially succeed under new scheme, since PC1 there still carried real variance — not bug, just no longer failure case).
- Any cached `<out>/tica/bootstrap_torsion_cv.json` from run predating this holds single raw eigenvector under old semantics; loaded as-is if present (`_ensure_bootstrap_torsion_cv_ready` in `gareus/production.py`), changing `bootstrap_torsion_component` on resumed run does nothing until cache file deleted and window/seed setup redone.

## GENPEPT contact-count bias

- Added `--contact-bias-strength` (default `0.0`, no behavior change) to `GENPEPT.py`: Metropolis-style soft acceptance bias per-conformer in `generate_one`, on top of existing energy/steric-only filtering.
- `accept_prob = min(1, exp(strength * (ccount - ref)))`. For `strength > 0`, `ref` = combinatorial max `contact_count` for sequence/`--contact-min-sep` (best-possible conformer always accepted, lower-contact ones progressively suppressed); for `strength < 0`, `ref = 0` (mirrored, favors fewer contacts).
- Motivation: GENPEPT's per-residue Ramachandran sampling has no compactness/contact bias anywhere (generation, basin-hop, NMA) — confirmed by A/B test on chignolin (`chignolin_genpept_r3` vs `_r4`, see project memory) where even switching to hairpin-tuned `diversity_bank_preset` only modestly enriched near-native density without shifting dominant (open) mode, per-residue sampling stays uncorrelated across residues.
- `ref` = loose combinatorial ceiling, often far above reachable — start with small `strength` (0.05-0.3). Values near/above 1.0 can crush acceptance to near-zero, exhaust `--n` before enough candidates found (reproduced: `strength=1.0` on chignolin with `--n 4000` raised `RuntimeError: Only 0 all-atom-valid candidate seeds found`; `strength=0.15` with `--n 8000` worked, shifted mean `contact_count` from 3.92 to 6.01 on 300-candidate pool).
- Applied consistently in both `generate_candidates` (initial pool) and `generate_adaptive_frontier_proposals` (explore-loop proposals) via shared `GenConfig.contact_bias_strength` field, so explore-loop rounds don't silently bypass bias.
