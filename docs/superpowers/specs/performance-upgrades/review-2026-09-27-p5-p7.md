Reviewers: three independent Claude Opus reviewers, each given `performance-upgrades/spec.md` §1–3 and §8–12 plus the measured facts, and each checking claims against the code. The multi-model board was abandoned: the model proxy stalled every run that day.

## Key findings

### Diagnosis (C)

Measured per 2000 steps (the least common multiple of the sample and exchange intervals):

| Setting | Wall time |
| --- | --- |
| Harness, no cap | 55.2 s |
| Harness, cap 8 | 34.8 s |
| Production, no cap | 63.3 s |
| Production, cap 8 | 61.9 s |

- If production's extra 8.1 s over the harness were a fixed cost, P3 would have given about +47 % in production.
- Instead, about 19 s per 2000 steps is **new cost created by P3 itself**.
- Joins between replicas explain only about 3–4 %: about 1.7 % from wave quantization and about 1.8 % from the tail of each wave.
- Likely cause: host-synchronous work inside the admitted turns. Each NPT attempt makes about 13 synchronous device round trips on the owner thread. There is one attempt every 200 steps, plus a trajectory frame read every 250 steps.
- With no cap, 59 replicas per GPU overlap that latency. The cap of 8 converts it into slot occupancy.
- The harness has no barostat, reporters, sampling or exchange, and it uses `UseBlockingSync=false`; production uses `true`. The harness therefore does not model production.
- P6 does not touch this cost, and its realistic ceiling is about 3–6 %.
- P3's measured +2.4 % also fails the spec's own ≥3 % promotion gate.

### P6 (A)

- **Critical.** `sample()` reads Context and integrator state on the coordinator thread (`production.py:7748`, `7754`, `7760`, `7803`: boost globals, integrator globals, recalibration energies, positions). This is safe only because of the all-replica join. Without the join it becomes a data race and a cross-thread CUDA hazard. Every such read must move to an owner-thread capture.
- **Critical.** The spec's "yield when output capacity is unavailable" cannot be expressed in the shipped dispatcher. `_remaining -= n` credits the planned step count, so a turn that yields early would silently leave a replica short of steps. A yielded replica is also requeued immediately, so it busy-livelocks.
- **Critical.** If the coordinator also drains the output queue, the system deadlocks: the coordinator is blocked in `run()` while owners wait on a full queue.
- P6 does **not** need helper-cpus. A minimal version, P6a, can ship first:
  - drop `next_log` from the chunk target;
  - capture scalars on the owner thread as a driver deadline;
  - assemble and write the tables synchronously at the next exchange boundary, before the exchange, flush and checkpoint.

  This needs no queues and no dispatcher change, and it cannot mislabel packets with the post-exchange assignment.
- Also needed:
  - an explicit order of operations at each boundary;
  - resume alignment of the capture deadline from the manifest's `next_log`;
  - batched swap application;
  - routing the boundary fetches through admission, since 236-way `getState` bursts undo P3;
  - an analysis of GIL contention.

### P5 (A, C)

- The helper-cpus allocator it extends does not exist; there is no affinity code at all. The spec should define a minimal standalone P5 built on `os.sched_getaffinity` and `sched_setaffinity`.
- It never states how a CUDA device ordinal maps to PCI bus ID, UUID and NUMA node. A wrong mapping pins threads to the wrong socket.
- It has no capacity rule for oversubscribed local masks.
- Native threads inherit the mask of whichever thread creates them: CUDA, pyarrow and OpenMP pools. They must be initialized before any thread is pinned.
- The first-touch arm is probably empty: contexts are already built on their owner threads.
- The CPU co-limit it targets was measured before P3 and needs re-measuring.
- Recommended first step: a launch-level `numactl` bound, and a 10-line environment-gated affinity setting on the owner threads.

### P7 (B, C)

- Every formula in §10.2 is correct for the shared layout, including the chain rule and the switching and torsion derivatives; all were checked in sympy against the code.
- Two gaps in the maths as written:
  - The spec uses a single N where the code has two: `N_c`, the mutable `contact_norm`, and `N_res`, a frozen literal.
  - It does not pin the clip-endpoint convention. Lepton gives T′ = 0 at lo and 1 at hi, while `anchor_partials` gives 0 at both.
- **High-severity integration seams:**
  - CV observations must be recomputed at the current coordinates. The legacy force does this, and the code comments claiming the values are cached are wrong.
  - `set_window` swallows `setParameter` errors, so misnamed parameters fail silently.
  - On resume, any unknown layout string maps to "split".
  - Fast-path force discovery uses `hasattr` duck typing.
  - The go/no-go gate cannot be falsified. It needs a CV-free ablation ceiling and an nsys count of synchronizations.
- `CustomCVForce` evaluates its outer expression on the host, which costs one device-to-host round trip per evaluation (inferred from the OpenMM 8.5.1 header). That is a real mechanism by which P7 could win, and P1 does not remove it.
- Effort is about 3–6 engineer-weeks plus deployment.
- Over-built items: periodic/triclinic support, virtual sites, parameter derivatives.

### Protocol (C)

- §12 costs about 150–200 node-hours, roughly 3–4 weeks of displaced chignolin_9 production.
- With n = 6 pairs, the gate effectively requires all six to be positive.
- It has no futility rule, and it is confounded by drift within a job (about 2.3 points between the two halves).
- The A1 reference cannot be built without helper-cpus.
- Cheaper alternatives:
  - Validate the harness against production before using it.
  - Screen in the harness with interleaved arms.
  - For settings that can change in-process, run ABBA blocks inside real production jobs. About 30 A/B pairs fit in one 4-hour job, for a standard error of about 0.2 %.
  - Use three jobs on different nodes, with a futility stop.

## Recommended order (C, consistent with A)

0. **Instrumentation.** Add phase timers around `step_all`, the sample fetch and its processing, the exchange fetch/decide/apply, and checkpoint plus scratch sync. Read the NPT `_timings` already stored in the baseline and P3 checkpoints. Record per-GPU NPT slot occupancy and CPU use under P3; optionally take an nsys trace. **Gate:** at least 80 % of the 19 s per 2000 steps is attributed.
1. **Cheap P3 follow-ups.**
   - Sweep the cap: 8, 12, 16, 24.
   - Move NPT and reporter synchronizations outside the step slot.
   - Defer sample post-processing, overlapping it with the next `step_all`.
   - Route boundary fetches through admission.
2. **P2 group-read reduction** on the NPT and sample paths.
3. **Real-space V_pep surrogate**, in parallel. It has the largest ceiling: removing the second PME could give up to about 2× per context.
4. ~~**P6a** (minimal, synchronous), only if sample-join idle is still ≥8 %; P6b (asynchronous) only with helper-cpus.~~ **Dropped 2026-09-27:** phase timers (job 2680578) put `sample` + `log` at 2.3 % of the loop.
5. **P7**, only if the CV-free ceiling is ≥10 % after P1 and the surrogate.
6. **P5**, only if CPU is still saturated and the numactl bound is ≥3 %; otherwise a launcher `numactl` line.
