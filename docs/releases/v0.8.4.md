# ATLaS-MD v0.8.4

ATLaS-MD v0.8.4 is the official release of the adaptive-CV and adaptive-λ work developed after v0.8.3: a slower, better-chosen CV2, a λ ladder that respaces itself, and adaptive machinery that can see and resolve the CV2 axis. It also brings the throughput, retention and analysis-memory work from the chignolin_9 campaign. Nearly all of the new sampling and adaptive behaviour is behind flags that are off by default; see "Changed" below for what differs for an existing configuration.

## Highlights

- **Slowness-ranked CV2 selection** (`--cv-selection-rank slowness`, the new default). Conditional tICA modes of the CV1-residualised torsion features join the residual PCs as candidates. The slowest candidate that is bimodal at fixed CV1 and reproduced across seed families is deployed. On chignolin_9's swarm this is psi(P4) + psi(D3) instead of the fast, single-peaked residual PC1.
- **Adaptive λ ladder** (`--ap-ladder-adapt respace`). A per-centre MBAR over each centre's rungs predicts the overlap at any λ. The ladder is then respaced atomically to the fewest rungs whose adjacent overlaps meet the target. On the chignolin_9 and chignolin_7 replays this gives [0, ~0.18, ~0.47, 1], with the 10th-percentile overlap of every rung pair at about 0.28.
- **Adaptive-CV2 machinery**, all opt-in:
  - one two-state MBAR edge metric for every CV2 gap (`--ap-edge-metric pairwise-mbar`);
  - a shape-based CV2 swarm layout, with springs from the local curvature (`--swarm-cv2-layout shape`);
  - reserved replica headroom (`--swarm-adaptive-reserve-fraction`);
  - R1-R3 resolution actions (`--ap-cv2-resolution`), with R3 flag-only by default;
  - per-window spring re-derivation (`--ap-cv2-respring`);
  - a "CV2 resolution" row in the health report.
- **Throughput and operations.**
  - Replica admission cap and MPS thread share (`--active-replicas-per-gpu`).
  - Production phase timers.
  - Checkpoint-generation pruning and retention tools: chignolin_9's campaign directory on aurum2 went from 520 GB to 140 GB.
  - Extensions that continue from end states instead of re-pulling every window.
  - A bounded-memory `gareus-analyze --low-memory`.
- **One MBAR solver.** Adaptive-side MBAR now uses gareus-analyze's numba-anderson solver throughout (chignolin_9 R2 solve: 43 s to about 1 s).

## Changed

- **Geometry edges on 2D/sparse layouts are now true neighbours.** Chains of non-neighbours used to create artefact weak edges. This fix is not behind a flag. It changes weak edges, bridge adds, retirement and the final connectivity gate on every 2D campaign; chignolin_9's final gate went from 6 weak spatial edges to 0.
- **Scheduled-phase allocation with top-ups off is a uniform per-state share.** The previous score allocator is removed. Campaign-end rung overlap is pairwise MBAR, not full-union.
- **New decision knobs are frozen per campaign.** They join `decision_settings.json`, so a deploy never changes a live campaign's rules. Turning a new feature on in an existing campaign needs `--ap-decision-settings-override`.

## Validation

The adaptive-CV2 work was validated before release:
- **T2 synthetic calibration** of the resolution knobs, independent and replica-exchange regimes.
- **T3 read-only replays** on chignolin_9 and chignolin_7.
- **An adversarial four-model review board**, whose conditions were all fixed or measured.

See `docs/superpowers/specs/2026-09-29-adaptive-cv2-validation/` (`t2_synthetic.md` section 9, `t3_retrospective.md` section 10).

Full suite on a clean export of the release branch: 4504 passed, 13 skipped, 1 xfailed, 9 failed, 15 errors. All 9 failures also fail on main:
- 3 docs assertions (they still expect the pre-rename "ATLAS-MD" casing);
- the Parquet-manifest `tiny_lambda_ladder` smoke test;
- `test_store`'s distance-logger persistence test;
- 4 mutation-battery tests that the correctness-core integrity guard now stops earlier.

The 15 errors are one test file (`test_cumulant_shared_computation.py`) that runs `git show HEAD:...`, which a git-less export cannot provide.

The release workflow re-checks the fast exchange-kernel suite, the official package version and a strict MkDocs build before publishing.
